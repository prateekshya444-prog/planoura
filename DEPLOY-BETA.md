# Planora beta deployment (Render + Vercel)

Fastest path to a public beta using the existing codebase. No Docker. Deploy from the branch that contains `render.yaml` and `vercel.json` (e.g. `cursor/beta-deployment` or `main` after merge).

## Architecture

| Layer | Platform |
|-------|----------|
| Backend API | Render Web Service (Node) |
| PostgreSQL | Render managed Postgres (linked via `render.yaml`) |
| Frontend | Vercel (Vite static build) |

## Prerequisites

- GitHub repo connected to Render and Vercel
- An OpenRouter API key (server-side only — never commit it)
- A strong JWT secret is auto-generated by Render (`generateValue: true` in `render.yaml`)

---

## Part 1 — Backend + database (Render)

1. Go to [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**
2. Connect `prateekshya444-prog/planoura` and select the branch with `render.yaml`
3. Click **Apply** — Render creates:
   - Postgres database `planora-db`
   - Web service `planora-api`
4. When prompted for sync-false variables, enter:
   - `OPENROUTER_API_KEY` — your OpenRouter key
   - `FRONTEND_ORIGIN` — leave blank for now; set after Part 2
5. Wait for deploy. Open the web service → **Settings** → note the public URL:
   - `https://planora-api.onrender.com` (name may vary)
6. Verify health:
   ```bash
   curl -s https://YOUR-RENDER-API-URL/health
   ```
   Expected: `{"status":"ok"}`

If the service crashes on first deploy, it is usually because `FRONTEND_ORIGIN` is empty while `NODE_ENV=production`. Set a temporary value, redeploy, then update after Vercel is live.

---

## Part 2 — Frontend (Vercel)

1. Go to [vercel.com/new](https://vercel.com/new) → import `prateekshya444-prog/planoura`
2. Branch: same branch as Render (with `vercel.json`)
3. Framework: **Vite** (auto-detected)
4. **Environment variables** → add:
   - `VITE_API_URL` = `https://YOUR-RENDER-API-URL` (no trailing slash)
5. Deploy. Note the production URL:
   - `https://planora.vercel.app` or `https://planora-xxxx.vercel.app`

---

## Part 3 — Wire CORS (Render)

1. Render → `planora-api` → **Environment**
2. Set `FRONTEND_ORIGIN` = your exact Vercel URL (e.g. `https://planora.vercel.app`)
   - Must match browser origin exactly: `https://`, no trailing slash
   - Optional previews: `https://planora.vercel.app,https://planora-git-main-username.vercel.app`
3. **Save** and **Manual Deploy** → Redeploy

---

## Part 4 — Rebuild frontend (Vercel)

If you set `VITE_API_URL` after the first deploy, trigger **Redeploy** on Vercel (env vars are baked at build time).

---

## Part 5 — Smoke test

1. Open the Vercel URL
2. Sign up → onboarding → add task → calendar → plan my day
3. DevTools → Network: API calls go to Render URL, status 200
4. Render logs: after planning, confirm you do **not** see `OpenRouter not configured; using deterministic scheduler`

## Environment variable reference

### Render (`planora-api`)

| Variable | Source |
|----------|--------|
| `NODE_ENV` | `production` (from `render.yaml`) |
| `JWT_SECRET` | Auto-generated by Render |
| `DATABASE_URL` | Auto-linked from `planora-db` |
| `FRONTEND_ORIGIN` | You set (Vercel URL) |
| `OPENROUTER_API_KEY` | You set (secret) |
| `PORT` | Set automatically by Render |

### Vercel

| Variable | Value |
|----------|--------|
| `VITE_API_URL` | `https://YOUR-RENDER-API-URL` |

## Build / start commands

| Service | Build | Start / output |
|---------|-------|----------------|
